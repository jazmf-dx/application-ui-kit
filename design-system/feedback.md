# Feedback

利用者が「何が起きたか」と「次に何をすればよいか」を理解できる表現を選びます。

| 状況 | 表現 | 原則 |
| --- | --- | --- |
| 入力項目の不備 | Field Error（`FormField` の `error`） | 対象フィールドの近くに理由を表示する |
| フォーム全体・業務ルールの不備 | `Alert tone="danger"`（テンプレートは `.alert .alert-danger`） | 送信前に解消すべき内容をフォーム先頭に置く |
| 継続して伝える注意・案内 | `Alert`（info / success / warning）。ページ幅なら `variant="banner"` | 利用者が対処または確認するまで残す。閉じられるのは読めば済む案内だけ |
| 保存などの一時的な成功・失敗 | Toast | 補助的な通知に使う。残す必要があるものは Alert |
| 削除など取り消しにくい操作 | Confirm Dialog | 対象と影響を明示してから実行する |
| データがない | Empty State | 読み込み失敗と区別し、次の操作があれば示す |
| 画面・機能を利用できない | Error State / Error Page | 原因と再試行・戻るなどの選択肢を示す |

- 入力エラーをToastだけで伝えない。
- 通常の保存・作成に確認Dialogを多用しない。
- 保存中は二重送信を防ぎ、入力内容を失わせない。
- 内部例外やstack traceを利用者に表示しない。
- loading、empty、error、disabled、長い文字列の状態を設計に含める。
