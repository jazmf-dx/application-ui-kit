# Colors

**色は見た目で選ばず、意味で選びます。**

トークン名は `primary` / `danger` のように**役割**を表します。
`company-blue` や `dark-gray` のような**見た目の名前は使いません**。
役割で名付けておくことで、アプリごとにブランドカラーを差し替えても
コードを書き換えずに済みます。

- 値の SSOT: `tokens/theme.css` の `@theme`
- 運用ルール: `ai-dev-standards/colors.md`

ステータス色をトークン化しないのは、**意味の数がアプリごとに違う**ためです
（案件ステータス・優先度・承認段階など）。無理にトークン化すると破綻します。

## アクションカラー

ボタン・操作系の色です。**1 画面に `primary` は原則 1 つ**にします。
主要な操作が複数あると、ユーザーは何をすべきか判断できません。

<ColorTable colors={ACTION_COLORS} />

固定ルール（迷ったらこれに従う）:

- **キャンセル・戻る → 必ず `secondary`**
- **削除・取り消し不可の操作 → 必ず `danger`**
- 保存完了・承認 → `success`

各トークンには `-hover` / `-active` / `-foreground` が対応しています
（例: `--color-primary-hover`）。ホバー色を自分で選ばないでください。

## ステータスカラー（意味 → 色）

**同じ意味の状態には全アプリで同じ色を使います。** アプリごとに別系統にすると、
後から統一するコストが跳ね上がります。

<StatusTable statuses={STATUS_COLORS} />

トーンは **背景 50 番台 + テキスト 500〜600 番台**に揃え、border は原則付けません。

application では色をテンプレートに書かず、`models.py` のプロパティで返します。
色の決定ロジックが 1 箇所に集まり、一覧・詳細・API で色がずれなくなります。

```python
@property
def status_display_class(self):
    return {
        "new": "bg-yellow-50 text-yellow-600",
        "in_progress": "bg-sky-50 text-sky-500",
        "closed": "bg-gray-100 text-gray-500",
    }.get(self.status, "bg-gray-100 text-gray-400")
```

```html
<span class="badge {{ obj.status_display_class }}">{{ obj.get_status_display }}</span>
```

意味を持たないローテーション色（出現順で循環させる色分けなど）を使う場合は、
例外であることをコード上にコメントで明示してください。

## 注意事項

- **インラインスタイルでの色指定は禁止**（`style="color: #3b82f6"`）。
  トークンを経由しないため、テーマ変更で置き換えられず、ダークモードにも追従しません
- **任意値クラスも禁止**（`bg-[#3b82f6]`）
- **クラス名は必ずリテラル文字列で書く**。`` `bg-${color}-50` `` のような動的組立は
  Tailwind が静的解析できずクラスが生成されません（灰色の箱になります）。
  条件分岐が必要なら、完全なクラス名を分岐の両側に書きます

```tsx
// ✗ 生成されない
<span className={`bg-${color}-50`} />

// ✓ リテラルで持つ
<span className={isDone ? 'bg-emerald-50 text-emerald-600' : 'bg-sky-50 text-sky-500'} />
```

- **色だけで情報を伝えない**。エラーは赤枠だけでなくメッセージも出します
  （色覚特性や、屋外での視認性の問題があります）
- コントラスト比は `基礎/文字` を参照してください
