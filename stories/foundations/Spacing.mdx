# Spacing

Tailwind のデフォルトスケール（**0.25rem = 4px 刻み**）をそのまま使います。
独自スケールは定義しません。

- 運用ルール: `ai-dev-standards/spacing-and-layout.md`

<DoDont
  doText={<>スケール上の値を使う。<Code>p-4</Code> <Code>gap-3</Code> <Code>mb-1.5</Code></>}
  dontText={<>任意値を使う。<Code>p-[13px]</Code> <Code>w-[300px]</Code> <Code>mt-[7px]</Code></>}
/>

任意値を許すと、同じ意味の余白が画面ごとに 1〜2px ずれて増殖します。
ずれは個別には気づかれませんが、画面を並べると不揃いに見えます。

## 固定ルール（値を 1 つに決めているもの）

同じ文脈で `mb-1` と `mb-2` が混在すると、フォームが縦に揺れて見えます。
以下は**値を 1 つに固定**しています。迷わずこれを使ってください。

<SpecTable
  head={['文脈', '値', '備考']}
  rows={SPACING_RULES.map((r) => [r.context, <Code>{r.value}</Code>, r.note || '—'])}
/>

React では `FormField` がこの余白を内部で適用するため、
**フォームを組むときは自分で余白を書かないでください**。

```tsx
{/* ✓ 余白は FormField が持つ */}
<div className="space-y-4">
  <FormField label="件名" required><Input /></FormField>
  <FormField label="担当者"><Select items={users} /></FormField>
</div>
```

ボタンと入力欄の左右余白は **14px（`px-3.5`）で揃えて**います。横に並べたときに

これらの余白は `tokens/theme.css` に定義済みです。

## アイコンと文字

「＋新規申請」のように**記号と文字が並ぶ**とき、左右を数学的に対称にすると
かえって不揃いに見えます。記号は字画が少なく、余白として読まれるためです。

これは余白スケールの変更ではなく、**アイコンが入ったときだけの光学補正**です。
Tailwind の 0.25rem 刻みという上の方針はそのまま維持しています。

### 2 つの規則

どちらも黄金比 φ = 1.618 から導出します（定義は `tokens/scale.css`）。

<SpecTable
  head={['対象', '式', '標準ボタンでの値']}
  rows={[
    ['アイコンがある側の padding', <>反対側の padding ÷ φ</>, '14 ÷ 1.618 = 8.65px'],
    ['アイコンと文字の間隔', <>文字サイズ × 0.4575</>, '14 × 0.4575 = 6.41px'],
  ]}
/>

`gap < アイコン側 padding < padX` の 3 段階になります。
出典は LiftKit（`registry/nextjs/components/button/button.css`）です。

<DoDont
  doText={<>アイコンは <Code>leftIcon</Code> / <Code>rightIcon</Code> に渡す（補正が自動で効く）</>}
  dontText={<><Code>{'<Button><Plus />新規申請</Button>'}</Code>（children に直接置くと、どちら側のアイコンか判別できず補正されない）</>}
/>

### アイコンの箱の補正

もう 1 つ、CSS だけでは解けない問題があります。**アイコンの CSS 上の箱と、
実際に描画される字形の幅が一致しない**ことです。

<SpecTable
  head={['アイコン', '描画される幅', '16px 枠内の片側の空き']}
  rows={[
    [<Code>Plus</Code>, '66.7%', '2.67px'],
    [<Code>Download</Code>, '83.3%', '1.33px'],
  ]}
/>

同じ `gap` を指定しても、`Plus` は `Download` より 1.33px 広く見えます。
そこで各アイコンの空きを**片側 1px に正規化**しています。字形もストロークの
太さも変えず、レイアウト箱だけを詰めます。実測値は
`tokens/icon-metrics.generated.ts`、一覧は 基礎/アイコン を参照してください。

**アイコンにサイズを手で指定しないでください。** `size="sm"` のボタンに
`<Plus className="w-4 h-4" />` と書くと、補正の計算基準（`--icon-box`）と
実際のサイズがずれます。サイズはボタンのサイズクラスが持っています。

<DoDont
  doText={<><Code>{'<Button size="sm" leftIcon={<Plus />}>'}</Code></>}
  dontText={<><Code>{'<Button size="sm" leftIcon={<Plus className="w-4 h-4" />}>'}</Code></>}
/>

コントロールの高さは **24 / 28 / 32 / 40px** の4段階で、ボタンと入力欄は同じ高さに揃えています。
主要なUIライブラリ（Ant Design、Fluent UI、shadcn/ui の全スタイル）が例外なくこの原則を採っており、
崩すと横並びにしたときに段差が出ます。高さは padding ではなく `h-*` で固定しているため、
枠線の有無で高さが変わりません。
**クラスを使えば自動で適用されるので、上から余白を打ち消さないでください**
（`class="card p-2"` のような上書きは、後で `card` を直したときに追従しません）。

## 要素間の余白

縦に並ぶ要素の間隔は、**個々の要素に `mb-*` を付けるより親に `space-y-*` を付ける**方が
崩れません。最後の要素にだけ余白が残る問題が起きません。

<DoDont
  doText={<><Code>{'<div className="space-y-4">'}</Code> で親がまとめて制御</>}
  dontText={<>子要素それぞれに <Code>mb-4</Code>（最後の要素に余分な余白が残る）</>}

## レスポンシブ

モバイルファーストで書きます。**素の指定がモバイル**、`md:` 以降で広い画面に上書きします。

```html
<!-- モバイル 1 列 → タブレット 2 列 → デスクトップ 3 列 -->
<div class="grid grid-cols-1 gap-4 md:grid-cols-2 lg:grid-cols-3">
```

| 接頭辞 | 最小幅 | 想定端末 |
| --- | --- | --- |
| （なし） | 0px | スマートフォン |
| `sm:` | 640px | 大きめのスマートフォン |
| `md:` | 768px | タブレット |
| `lg:` | 1024px | ノート PC |
| `xl:` | 1280px | デスクトップ |

各 Story はツールバーの **Viewport** で Mobile / Tablet / Desktop に切り替えて確認できます。

### 注意事項

- **横スクロールを発生させない**。テーブルは親を `overflow-x-auto` で包みます
  （`Table` は内部で対応済み）
- **タップ領域は最低 44×44px** を確保します。`btn-xs` を並べる場合は
  周囲に余白を取ってください（`ai-dev-standards/accessibility.md`）
- モバイルで `px-8` のような大きい左右余白を使うと本文幅が足りなくなります。
  左右余白は `px-4 md:px-6` のように広げてください
